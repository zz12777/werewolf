# 🐺 狼人殺小分隊法官助手

面對面狼人殺自動化法官工具，支援 6～16 人局多種板子配置，涵蓋完整場次（不只第一天）：夜晚各角色技能結算、警長競選、白天發言投票、勝負判定、遊玩數據排行榜、特別獎項統計。

## 快速開始

純前端專案，不需要安裝、不需要伺服器。

1. 下載整個資料夾（保持資料夾結構，不要只抓 `index.html`）
2. 雙擊 `index.html`，用瀏覽器直接打開即可

> 因為所有 `<script>` 都是傳統寫法（沒有用 ES module），本機用 `file://` 直接開啟就能正常運作，不需要架設本機伺服器，也不需要上傳到 GitHub Pages 才能預覽。

## 檔案結構

```
├── index.html              # 唯一 HTML 入口，各畫面以 div 切換顯示/隱藏
├── style.css                # 全域樣式
├── data/
│   └── games-history.js     # 歷史對局紀錄（GAMES 陣列，純資料，會持續增長）
└── js/
    ├── core.js               # 全域狀態、共用工具函式（玩家查找、死亡結算共用邏輯、存讀檔、即時同步）
    ├── sheriff.js             # 警長競選全流程（候選、發言、退水、投票、PK、發言方向、警徽交接）
    ├── night.js               # 夜晚各角色睜眼／技能結算邏輯
    ├── day.js                 # 白天流程（天亮公告、發言、投票、PK、遺言、開槍鏈）
    ├── steps.js               # 主要畫面調度函式 jgRenderStep()，依目前步驟渲染對應畫面
    ├── rules-ui.js            # 規則介紹分頁（角色卡片、板子資料、專有名詞、攻略、問題回報）
    ├── awards.js              # 特別獎項計算
    ├── playdata-core.js       # 遊玩數據分頁：排行榜統計、積分、成長趨勢圖
    └── main.js                # 初始化與啟動流程（必須最後載入）
```

### 載入順序

`index.html` 裡的 `<script>` 標籤順序是刻意排的，改動時請維持這個順序：

```
data/games-history.js → core.js → sheriff.js → night.js → day.js
→ steps.js → rules-ui.js → awards.js → playdata-core.js → main.js
```

`main.js` 必須放在最後——裡面的程式碼會在頁面載入當下立刻呼叫其他檔案定義的函式（初始化畫面、抓雲端資料），如果放在前面，會因為對應函式還沒被定義而報錯。其餘檔案彼此之間主要是函式/常數宣告，理論上互相呼叫不受載入順序影響，但仍建議維持現有順序，避免意外。

## 開發準則

- 新增邏輯時，依照上面的檔案分工放進對應檔案；不確定放哪裡，優先參考該功能「屬於哪個遊戲階段」（夜晚/白天/警長競選）或「是不是共用工具」。
- `jgRenderStep()`（`steps.js`）目前是一個涵蓋所有步驟的大函式（if/else 依 `step` 名稱分流），新增畫面步驟時在裡面加一個分支即可；如果之後想拆得更細（每個步驟各自獨立函式，類似角色渲染各自獨立），屬於架構升級，動手前建議先確認現有場次都測過一輪，降低回歸風險。
- `data/games-history.js` 只放歷史對局的原始資料，不要把邏輯寫進這個檔案。
- 所有使用者看到的文字、程式碼註解一律使用繁體中文。
